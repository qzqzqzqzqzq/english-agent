# English Agent 产品定义（V1）

状态：用户已确认，可作为首版实现依据。  
项目：qzqzqzqzqzq/english-agent  
整理日期：2026-09-28

## 1. 产品目标

做一个供个人本地使用的英语对话网页。用户以英语练习自然对话；遇到 AI 回复中的生词、短语或句子时，可即时看中文释义、翻译或继续追问语法。

## 2. 首版范围

- 本地运行的浏览器网页，个人单用户，纯文字。
- 支持新建和保存多个彼此独立的对话。
- 默认自由聊天，也提供内置情景和自定义情景。
- 首发内置情景：日常闲聊、咖啡馆/餐厅点餐、旅行、购物、工作交流。
- 首版不做语音、多人账号、云同步和外部材料阅读。

## 3. 对话规则

### 主模型

- 主模型负责日常对话；用户发送的每条消息（英文、中文或中英混合）都进入主对话。
- 默认自然交谈；除非用户主动询问或开启主动纠错，否则不主动解释或纠错。
- 默认鼓励用英语。用户用中文求助时，AI 仍以英语接话；需要说明时再用中文解释。
- 纯中文内容不算英语错误。主动纠错开启时，可以在纠错卡片中给出自然的英语表达。
- 中英混合内容只纠正其中的英语部分，也可以给中文部分提供自然英语表达。

### 每个对话独立的设置

- 英语难度：简单、常规、挑战；新对话默认常规，可随时修改，之后的回复使用新设置。
- 主动纠错：关闭、轻度、标准、严格；新对话默认关闭，可随时修改。
- 建议的纠错挡位：
  - 关闭：不主动纠错。
  - 轻度：只指出影响理解或反复出现的问题，简短修正。
  - 标准：指出明显语法、搭配和不自然表达，并给简短中文说明。
  - 严格：指出所有明显错误，给完整改写和中文说明。
- 正常对话回复与纠错卡片分开展示；纠错卡片排在自然对话回复之后。
- 英语难度也影响辅助解释里给出的英语例句难度，中文解释保持易读。

## 4. 划词辅助

仅针对 AI 发来的消息提供划词操作：

- 选中单词或短语：立即显示对应中文释义。
- 选中完整句子：显示整句中文翻译，并提供“追问语法”入口。
- 只有用户点击“追问语法”并发送追问时，才启动该句子的辅助对话。
- 每条 AI 消息拥有独立的辅助追问记录；同一条消息中的同一句可以连续追问，不同消息之间互不混淆。
- 辅助模型只接收当前选中内容、对应完整句子和附近少量对话，不发送主对话的完整历史。
- 主模型与辅助模型使用各自独立的中转站配置；即使使用同一中转站，也分别配置。

## 5. 历史记录和原生 Compaction

- 常规阶段按默认行为向主模型发送完整对话历史。
- 接近上下文上限时，使用用户指定的原生 Compaction，不使用提示词要求模型写摘要的方式。
- 用户已选定单独压缩端点方案：达到阈值时调用 OpenAI Responses API 的 /v1/responses/compact。
- 压缩只影响发给模型的上下文窗口；本地仍完整保存和展示原始对话。保存压缩后的机器上下文，用于后续请求。
- 若中转站或模型不支持 Responses / compact，应明确提示兼容性问题，不能悄悄改成提示词摘要。

## 6. 设置、数据与密钥

- 网页设置页提供两套独立配置：主模型、辅助模型。每套至少包含 Base URL、API Key、Model ID 和连通性测试。
- API Key 由用户在本机设置页输入；不得提交到 Git、放入前端源码、浏览器持久存储、提示词、日志或测试夹具。保存后不向前端返回明文。
- 对话与设置仅保存在本机；建议由本地后端访问本地 SQLite 或等价本地存储。
- 本地服务只监听 localhost / 127.0.0.1，不提供公网访问能力。
- 用户提供的候选中转站是 xindu.xyz。第三方检测页列出的 API Base URL 带 /v1，但其测试只覆盖 Chat Completions；本项目未能收到 Responses / Compaction 测试响应。因此 URL 应保持可编辑，不能声称已验证支持。
- Prompt caching 属于提供方/中转站能力，不实现伪本地计费缓存。保持静态系统提示词等稳定前缀，若响应提供缓存用量则展示或记录，不能假设一定有缓存折扣。

## 7. 兼容性与验收

- 能分别保存、编辑、测试主模型和辅助模型配置；两套可使用相同或不同服务。
- 主模型可创建多个独立对话，刷新后历史仍在；对话设置互不串用。
- 对 AI 回复的选词释义、整句翻译、句级语法追问和每消息独立辅助记录按上述规则工作。
- 纠错卡片只在对应对话开启主动纠错时出现，且按所选挡位执行。
- 压缩前后完整 transcript 在 UI 中保留；后续模型上下文使用 compact 端点返回的原样机器窗口。
- 用 mock / fixture 覆盖业务逻辑与 API 解析，不用真实 API Key 跑测试；设置页连接测试只在用户主动触发时发送。
- README 说明依赖安装、本地启动、配置方式和已知中转站兼容性限制。

## 8. 当前外部验证结果

已尝试发送最小化 Responses 请求并查询模型列表，但执行环境连接 xindu.xyz 超时，没有获得 HTTP 响应；公开文档页面也返回 502 Connection refused。这不能证明中转站支持或不支持。一个第三方检测报告只验证 Chat Completions 协议字段，没有验证 Responses 或原生 Compaction。

OpenAI 官方文档描述了 Responses 服务端自动 Compaction 和单独 /responses/compact 两种原生方式。本项目按用户选择使用后一种。
