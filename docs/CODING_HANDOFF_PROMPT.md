# 给编码模型的启动提示词

请在当前仓库 qzqzqzqzqzq/english-agent 中正式实现 English Agent 首版。先检查仓库现有文件、README、AGENTS.md（若存在）和项目级技能，再完整阅读 docs/PRODUCT_BRIEF.md。该产品定义已由用户确认；不要重新询问已定的产品问题。工程细节可自行选择，但要遵守产品定义并在 README 记录重要取舍。

## 首版实现目标

做成一个可在本机启动的单用户英语对话网页，完整打通“多对话管理、主模型对话、主动纠错、AI 回复划词翻译、逐消息语法追问、分开的主/辅助模型设置、本地持久化、原生 Compaction”。

如果仓库没有既定技术栈，优先使用 React + TypeScript + Vite 前端、Node.js + TypeScript 本地后端和 SQLite。服务只监听 127.0.0.1。先做一个能实际运行的端到端 MVP，再完善细节；不要只输出方案或伪代码。

## 必须遵守的行为

- 多个独立对话；默认自由聊天，首发情景为日常闲聊、咖啡馆/餐厅点餐、旅行、购物、工作交流，并允许自定义情景。
- 每个对话单独保存难度（简单、常规、挑战，默认常规）和主动纠错挡位（关闭、轻度、标准、严格，默认关闭），可在对话中途修改。
- 所有用户输入都进入主对话。AI 默认用英语自然接话；中文求助也用英语回应，需要说明时才用中文。
- 纯中文不算错误；纠错开启时可在纠错卡片中给自然英语表达。中英混合时只纠正英语部分，也可翻译中文部分。
- 主模型的自然回复与纠错卡片分开呈现。纠错卡片放在自然回复之后。纠错挡位含义见产品定义；难度也影响辅助解释中的英语例句。
- 在 AI 回复上选单词或短语，立即显示中文释义；选整句显示翻译并给“追问语法”入口。追问才创建或继续该 AI 消息独有的辅助线程。
- 辅助请求只带选中内容、对应完整句子及附近少量对话；不能把主对话全量历史发送给辅助模型。
- 设置页包含互相独立的主模型和辅助模型配置（Base URL、API Key、Model ID），支持测试连接；两组配置可以使用同一个服务。
- 完整聊天记录始终保存在本机。API Key 仅由本地后端保存和读取，不放进代码仓库、浏览器持久存储、日志、提示词、截图或测试夹具；保存后不要把明文返回前端。不要使用用户在聊天里贴过的密钥。
- 本地数据可用 SQLite；为数据库、环境文件、日志和构建产物补齐 .gitignore。

## 主模型 API 与 Compaction

- 主模型走 OpenAI Responses API，以支持原生 Compaction。接近上下文阈值时，按已确认的决定调用单独端点 POST /v1/responses/compact；后续请求使用端点返回的压缩窗口原样续接。
- 同时保留本地完整 transcript 和压缩后的模型上下文。压缩不能删除或改写 UI 中展示的历史。
- 不得用提示词让模型生成摘要来冒充原生 Compaction。若中转站不支持 Responses 或 compact，清楚报告兼容性问题，不能静默降级为提示词摘要。
- 当前候选中转站 xindu.xyz 的 Responses / Compaction 兼容性尚未验证：公开第三方检测只覆盖 Chat Completions，实际短请求未收到 HTTP 响应。将 URL、模型 ID 和端点保持可配置；开发测试使用 mock，不要把“已验证兼容”写入 UI 或文档。
- API 错误要对用户可读并区分鉴权、模型名、网络和端点不支持；不要在错误信息中泄露 Key。
- Prompt caching 由提供方/中转站决定。保持静态系统指令等稳定前缀；只在实际 usage 返回字段时显示缓存用量，不自行伪造缓存或节省金额。
